# استقبال حزم مصادر متجر الأغبري — للمصالحة والتدقيق فقط

هذا المسار مخصص لاستقبال وفهرسة الأرشيفات قبل تحديد مستودع المتجر الهدف. **لا ترفع الملفات الثنائية الكبيرة كملفات Git عادية** ولا تدمج شيئًا في `main` التشغيلي من هذا المسار.

## الأرشيفات المنتظرة

1. `AGHBARI_COMMERCE_UNIFIED_SOURCE_PACKAGE.zip` — النسخة الموحدة السابقة (ذُكر أنها قرابة 90.9–95.4 MB؛ يلزم استعادة الملف الأصلي والتحقق من الحجم والبصمة).
2. الأرشيف المضغوط الذي يحتوي على 7 مشاريع.
3. الأرشيف المضغوط الآخر الذي يحتوي على عدة مشاريع.

## مكان رفع ملفات ZIP الكبيرة

استخدم مرفقات GitHub Releases في مستودع الاستقبال، وليس زر Upload files داخل هذا المجلد؛ فمرفقات Release مناسبة للأرشيفات الثنائية الكبيرة، بينما ملفات Git العادية لها حدود رفع أصغر.

صفحة إنشاء إصدار/مرفقات:
https://github.com/Report-Engainall/report-insight-engine/releases/new

عنوان مقترح للإصدار:
`commerce-source-intake-2026-10-16`

اسم الإصدار:
`Commerce Source Reconciliation — Archive Intake`

ارفع الأرشيفين الجديدين كمرفقات منفصلة، مع إبقاء أسماء الملفات كما هي. لا تنشر مفاتيح أو ملفات بيئة أو أسرارًا.

## حالة الحزمة السابقة

الرابط السابق الذي جُرّب للحزمة الموحدة يعيد `410 Gone` حاليًا؛ لذلك لم يتم استرجاع ZIP ولم تتم إضافته إلى GitHub. يلزم إعادة رفع الملف الأصلي أو تزويدي برابط مباشر جديد صالح قبل إجراء فحصه أو حساب SHA-256 له.

## سياسة المعالجة

- حفظ كل أرشيف أصلي كما ورد وعدم تعديله.
- تسجيل الاسم والحجم وSHA-256 بعد التنزيل.
- جرد الملفات والتواريخ والفروع والترحيلات والاختبارات وسجلات الاختلافات.
- إزالة التكرار المطابق دون حذف النسخ الفريدة أو التاريخ المفيد.
- مقارنة المصادر وتوثيق التعارضات والتبعيات قبل اتخاذ قرار الدمج.
- عدم إجراء أي تغيير في مستودع المتجر الهدف حتى يزوّد المالك رابطه وتُراجع المصادر.
- لا يُعد نجاح فك الضغط أو البناء دليلًا منفردًا على اكتمال المتجر أو صلاحية الإنتاج.


## مسار الجمع الفعلي وحزمة المصدر المرجعية

أُضيف فاحص آلي للمستودعات والفروع والوسوم ومراجع PR في tools/build_source_package.py ويُشغّل عبر GitHub Actions. يقرأ المصادر دون الكتابة إليها أو دمج فروعها؛ يحفظ النسخة الأساسية، والفروقات والملفات الفريدة، وسجل البصمات والتعارضات، وينقّح الأسرار المعروفة قبل إنشاء الأرشيف.

تُحفظ جداول الجرد في 01_SOURCE_INVENTORY/. يوضع ZIP الكبير كمرفق GitHub Release بدل ملف Git عادي. إذا لم يصل ملفان ZIP على الأقل في إصدار الإدخال commerce-source-intake-2026-10-16 فالنتيجة تسمى AGHBARI_COMMERCE_GITHUB_BASELINE_SNAPSHOT.zip صراحةً، وليست الحزمة النهائية. بعد إرفاق أرشيف المشاريع السبعة والأرشيف متعدد المشاريع ونشر الإصدار، يعاد تشغيل الجمع وتُنشأ الحزمة الموحدة.

التحقق PASS يثبت سلامة الأرشيف وإعادة استخراج الملفات ومقارنة البصمات فقط؛ ولا يثبت build/test أو نجاح المتجر على الإنتاج. الملفات الحساسة تُستبعد أو تُنقّح، ولا تتغير مستودعات المصدر.
