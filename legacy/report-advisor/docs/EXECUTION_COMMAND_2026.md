## Product UI/UX transformation gate — NON-BOLT / COMMERCIAL GRADE

The authoritative visual/product reference is the existing **Master UI/UX Product Design Prompt** for Report-Advisor / الأغبري. It is a product-quality specification, not a template source.

### Mandatory direction
- **Do not use, preserve, or imitate a Bolt-style template, generic admin dashboard, marketing landing-page aesthetic, chatbot-first shell, or unrelated artboard collection.**
- The target is a **radical product-level transformation of the existing application experience** while preserving the existing authoritative technical architecture, canonical data paths, tenant/RLS model, import lifecycle, evidence/provenance model, and business capabilities.
- The reference images in project/library are **visual inspiration for hierarchy, density, palette, spacing, and composition only**. They are not a screen-by-screen design source and must not be copied as the implementation.
- Do not rebuild already-correct backend/runtime paths merely to support visual work.
- Do not add decorative UI that has no business purpose.

### Screen acceptance bar
Every major surface must answer, visually and operationally:
**what is happening → why it matters → whether it is trustworthy → what evidence supports it → what requires attention → what decision/action is available → what happens next.**

Every important result should expose, where applicable:
- result/value;
- reporting period;
- source;
- formula/definition;
- tenant/company context;
- as-of/freshness;
- evidence/confidence;
- status;
- limitation/block reason;
- next action.

### Product-wide visual requirements
- Arabic-first, RTL-native, enterprise-grade information density.
- One coherent application shell across desktop, tablet, and mobile.
- Premium restrained visual system: deep ink / green-black, teal/emerald primary, controlled amber accent, restrained semantic colors, white/light neutral surfaces.
- Strong hierarchy, consistent spacing, typography, tables, charts, badges, drawers, dialogs, filters, breadcrumbs, and responsive behavior.
- No excessive gradients, glassmorphism, giant decorative KPI cards, random rounded-card mosaics, childish gamification, fake AI sparkle, or visual noise.
- Progressive disclosure for dense business information; mobile uses touch-safe controls and bottom/action patterns where useful.
- State coverage is part of the product, not an afterthought: loading, empty, error, review, blocked, unavailable, insufficient-data, verified/trusted, and demo/sample where appropriate.
- Evidence UI is a reusable product pattern, not a page-specific trick.
- Decision UX must connect evidence → recommendation → decision candidate → approval → action → outcome without visually claiming persistence that the runtime has not proven.

### Existing product foundation must be preserved
Use the current App Shell, Sidebar, Header, Command Palette, routing, lazy loading, reusable components, canonical data services, and authoritative server/database boundaries as the foundation. Improve and unify them; do not replace them with a template architecture.

The finished product must read as:

A serious commercial intelligence/decision operating system suitable for real business use, executive review, analyst workflows, operational work, document intelligence, reporting, and sales/demo presentation.
